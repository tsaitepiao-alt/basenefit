# basenefit — 雲端同步設定（Google 試算表當資料庫）

做完這 6 步，學員／教練在不同手機上就會看到同一份資料。**不用付任何費用。**

## 步驟

1. 打開 https://sheets.new （**用 tsaitepiao@gmail.com 登入**）→ 建立一份新試算表，命名例如 `basenefit 資料`。
2. 上方選單 **擴充功能 → Apps Script**。
3. 把左側 `Code.gs` 的內容全部刪掉，貼上這個資料夾裡的 **`Code.gs`** 全文，按 💾 儲存。
4. 右上角 **部署 → 新增部署作業** → 齒輪選 **網頁應用程式**：
   - 說明：`basenefit api`
   - **執行身分：我（tsaitepiao@gmail.com）**
   - **具有應用程式存取權的使用者：任何人**
   - 按 **部署** → 第一次會要求授權：選「進階」→「前往（不安全）」→ 允許
     （會出現「不安全」是因為這是你自己寫的未驗證腳本，只有你自己的帳號會用到，正常）
5. 複製產生的 **網頁應用程式網址**（結尾是 `/exec`）。
6. 回到 basenefit 網站 → **學員與設定 → 雲端同步** → 貼上網址 → 按「儲存網址」。
   - 之後按 **上傳到雲端**（把本機資料寫進試算表）或 **從雲端下載**（把手機／電腦的資料拉回來）。

## 注意

- 網址**每次重新部署都會變**，換了新網址記得重貼一次。
- 資料存在你自己的 Google 試算表的 `basefit-state` 工作表裡（一列一片，每片 4 萬字元，**這是為了避開 Google 單格 5 萬字元的上限**）。
- 想備份：直接在試算表「檔案 → 下載」即可；想還原就把那些片接回 JSON 丟進網站（或改用自己的 Apps Script）。
- 目前設計是「整份資料覆蓋」：**上傳前建議先按一次「從雲端下載」**，避免兩台裝置互相蓋掉。之後要做「多人同時編輯自動合併」需要更完整的後端（屆時可改用 Firebase 或 Supabase）。

## 容量與費用（20 位學員的實測）

| 項目 | 實測／官方上限 | 20 人用起來 |
|------|----------------|-------------|
| 網站大小（GitHub Pages） | 1 GB（免費） | 網站本體 46 KB → 用掉 0.005% |
| 網站流量（GitHub Pages） | 100 GB/月（soft） | 約 230 萬次瀏覽/月 |
| 試算表格數 | 1,000 萬格 | 20 人一年的紀錄約 12 列 → 用不到 1% |
| 單一格字元 | 50,000 | 分片後每片 40,001 → 安全 |
| Apps Script 執行 | 6 分/次、90 分/天 | 每次同步不到 1 秒，遠遠用不完 |
| **影片檔** | Google 免費 15 GB | 20 人 × 4 支/月 × 25 MB = 2 GB/月 → **約 7.7 個月見底** |

**結論**：文字資料（訓練紀錄、評估、留言）完全免費、用不完；**唯一會爆的是影片檔**。
影片要免費的話，建議「影片放 YouTube 不公開、網站只存連結」，或把影片壓到 5 MB 以內（可撐約 38 個月）。

## 政策提醒（重要）

GitHub 的 Pages 條款寫明：不得當作免費主機來跑**商業網站／電商／SaaS**。
如果你有向學員收費，嚴格說踩在灰色地帶 → 建議改用 **Cloudflare Pages** 或 **Netlify**（免費方案允許商業用途，做法一樣是把 `index.html` 拖上去）。
